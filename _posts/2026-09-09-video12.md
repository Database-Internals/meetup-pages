# Доклады

## DataFusion в Tarantool Column Store: ограничения движка и способы их обхода.

**Артем Новиков, Старший Backend-разработчик, Tarantool, VK Tech (со-автор доклада Альберт Скальт, Старший Backend-разработчик, Tarantool, VK Tech)**

В докладе рассмотрели устройство колоночной СУБД для транзакционно-аналитической обработки данных в реальном времени Tarantool Column Store, где в качестве движка запросов используется DataFusion. Это достаточно известный движок с открытым исходным кодом и, казалось бы, легко расширяемый, с превосходной производительностью и богатым функционалом. Однако, тут есть свои нюансы и ограничения. Рассказали о тех, с которыми команда столкнулась при разработке TCS, и о том, какие решения были приняты:

- как решили проблему высокого latency обработки запросов из-за перепланирования,
- как при разработке шардированного колоночного хранилища решали задачу обработки распределенных SQL запросов, какие идеи пробовали и на чем остановились,
- какие из патчей смогли уйти в upstream, а где пришлось идти на компромиссы.

## Marrying OLTP+OLAP with Dynamic Tables in YTsaurus

**Руслан Савченко, Руководитель службы разработки динамических таблиц в Яндексе**

В базах данных принято различать OLTP и OLAP: первое требует большого количества небольших строго изолированных транзакций, тогда как второе предполагает гораздо более ресурсоёмкие запросы, но с гораздо меньшей частотой. СУБД обычно ориентированы на один из этих сценариев — если не по изначальному замыслу, то просто вследствие фокуса оптимизаций в течение жизненного цикла. Перенести тяжёлую OLAP‑нагрузку в СУБД, оптимизированную под OLTP — весьма непросто, однако в случае успеха можно получить ряд преимуществ: меньше систем для обслуживания, надёжные гарантии при загрузке данных, упрощённое распределённое шардирование.

В докладе было рассказано о миграции масштабной базы данных из ClickHouse в динамические таблицы YTsaurus. ClickHouse — широко известная OLAP СУБД. Динамические таблицы YTsaurus — СУБД класса NewSQL, которая активно используется внутри Яндекса. Разобрали, какую разработку провела команда, чтобы адаптироваться к модели данных ClickHouse, и какие оптимизации реализовали, чтобы динамические таблицы YTsaurus смогли обрабатывать аналитические запросы с нужной производительностью.
